# エージェント計画

2026-11-09 改訂。2026-11-08 の案（別チャットを足し、既存アプリを順に呼ぶ）は、この文書で置き換える。

対話のループはノートブックにある。`backend/app/agent.py` は実験で、第二の入口にはしない。

## 方針

エージェントは、ノートブックの対話を厚くしたものである。源内 OSS Ver.2 は待たない。源内工房、Pi、Hermes を、この製品の実行系としては同梱しない。

職員が読むのは、章のある文書である。情報化企画書ナビが Excel の欄（背景、業務、現行、目標）へ書き戻すのと同じで、見出しと本文が残る。汎用のヒアリングシート（`項目` と `回答` の2列、行 `生成指示`）は、その文書を職員に渡す形にはしない。アプリ間の契約として内部に残す。

## 職員が見る流れ

1. ノートに資料を置く。条例や規程は、いまどおり取込時に節へ分ける。共有ナレッジは参照でき、ノートへ入れるかは人が決める。
2. 対話が項目の下書きを置く。文書の下書きは章の見出しで書く。人が「項目に追加」すると、見出しごとに項目へ分かれる。AIタイプ（議事録係など）は、今どおり書き方の手順である。
3. 人が項目を採用する。採用したものが正本である。エディタを開くかどうかは、その次に人が選ぶ。
4. 「項目」の隣に「Markdownエディタで編集」タブを置く。項目タブの「記入済みシートをダウンロード」と一覧の「空の雛形」は出さない。生成指示はこのタブに置く。シートは、このタブから渡すときの内部データである。
5. タブでは渡し先を選ぶ。新しいプロジェクトにするか、自分の既存プロジェクトに章を足すか。新規の名前はノートの題名を初期値にする。既存へ足すときは、同じファイル名（`生成文書.md` や `01_見出し.md`）が上書きされることを画面に書く。ノートの新規作成と、エディタの空プロジェクト作成は、それぞれの画面に残す。
6. 確定すると、エディタがそのプロジェクトを用意し、「ヒアリングシートから生成」で章を入れる。項目名が見出し、回答が本文になる。開くのはその編集画面である。章の手直し、図、書き出しはエディタの操作のまま行う。

xlsx のダウンロードと、エディタへのアップロードは、人が運ぶ作業ではなくする。

情報化企画書のように欄が決まっている文書は、情報化企画書ナビのシートを正とする。汎用ノートの2列表で、その欄を置き換えない。

## 対話に足す道具

今のループは、参考資料の検索、項目の参照、共有ナレッジ、下書きを置く、編集タブを開く、最大12ステップである。項目の確定はしない。

| 道具 | 動き |
| --- | --- |
| 下書きを置く | 未採用の項目をまとめて置く。正本にはしない |
| エディタで開く | 「Markdownエディタで編集」タブで渡し先を決め、章を入れた編集画面を開く |

シェル、作業ディレクトリ、任意のファイル作成は足さない。Word や PowerPoint への合成は、開いたあとの編集画面に残す。テーマの無い自由な Excel も足さない。

ステップ数の上限は12である。資料を探して下書きを置き、頼まれたときだけ編集タブを開くまでを、1つの対話で終える。

## ファイルサーバ

Storage Manager の Hermes は、ファイルサーバを利用者の付与範囲で調べる側である。ノートの実行系にはしない。

ファイルサーバにしかない資料が要るとき、本人の Hermes へ A2A で1タスクを送る。返るのは出典（パス、タイトル）つきの文章である。ファイルの移動、保存先の適用、シェルは含めない。ノートの参考資料に足すかは人が決める。

条例や規程の条文は、ノートに取り込んだ資料と共有ナレッジを正にする。同じ検索を Hermes に二重に頼まない。A2A の口は利用者向けプロキシには出さない。利用者の識別子は backend が署名し、Open GENAI の利用者と Storage Manager の `X-Wm-User` の対応は導入ごとに持つ。

この連携は、ノートから文書が開くまでが動いてからにする。

## 範囲の外

- 源内工房に当たる、利用者ごとのコード実行環境
- Pi や Hermes をノートの土台にすること
- 別のエージェントチャット画面
- 利用者管理、監査、モデル制御、禁止語、Web SSH を対話の道具にすること
- 手続きの提出や、文書の確定を対話が代行すること。確定はエディタと、それぞれの画面に残す
- スキルの組織横断共有（源内ライブラリ）

ナレッジ MCP（`:8002`）は無認証で `scope` を指定できる。対話からはノートのサーバがスコープを固定して呼ぶ。今のノートと同じである。

## 段階

1. **編集画面で開く** — 「項目」の隣に「Markdownエディタで編集」タブを置き、新規プロジェクトか既存プロジェクトかを選ばせる。確定後に章の入った編集画面を開く。項目タブのダウンロードボタンは外す。ノートとエディタの新規作成は残す。書き出しはエディタの既存の操作のまま。
2. **対話を伸ばす** — 下書きを置く道具をループに足してある。検索から「エディタで開く」までを1つの対話で終える。項目の採用は人が行う。編集タブを開いても、プロジェクトは作らない。
3. **A2A** — ファイルサーバの調査結果を、参考資料に足す候補として対話に返す。

段階 1 の完了は、エディタのプロジェクト一覧にその案件が乗り、開いた編集画面で章の見出しと本文が読めること、である。空の新規プロジェクトでエディタだけを使う流れは、そのまま残る。
