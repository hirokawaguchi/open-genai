# エージェント計画

2026-11-27 改訂。ノートの対話の実行系は Hermes にする。別のチャット画面は作らない。

## 方針

ノートを開いて話す。何を作るかが対話で一文のゴールになるまで、節の選び方や生成指示は聞かない。ゴールが決まったターンで資料を調べ、項目へ書く。確認は、資料が矛盾しているときと、必要な事実が資料に無いときだけ。項目が揃ったら、そのゴールを生成指示として Markdown エディタへ渡す。生成指示はゴールと別の文ではない。

画面はノートブックのままである。一覧、参考資料、対話、項目のタブは残し、参考資料と項目の中身は見える。項目の手修正も残す。原稿の編集画面は回答から開く。生成指示の入力、章の採用、渡し先の選択は画面に出さない。初回はノートの題名で新しいプロジェクトを作り、同じノートの二回目以降は同じプロジェクトへ足す。

## 実行系

Hermes はノートの対話の中で動く。コンテナの単位は、今の棟、今のチーム、その利用者である。チームに一つ、利用者に一つ、にはしない。権限の判定は台帳に残し、コンテナへ渡す署名はそのチームの範囲だけにする。

共有の作業ディレクトリは作らない。コンテナのディスクは、無操作 1800 秒で捨てる一時領域である。同時数の既定は 4。`/storage`、`/mail`、モデルの重みはマウントしない。Hermes のイメージが未設定のあいだは、同じ道具をノートのプロセスで実行する。`NOTEBOOK_HERMES_DOCKER=1` のときだけ一時コンテナを起動する。

ファイルとして残すものは台帳へ書く。文書ファイルは棟の文書台帳の下書きである。確定、削除、手続きの提出はしない。台帳が止まっているときは、別の場所へ書かず確認して止まる。ナレッジへのファイル投入は、検索のためだけにする。

## 道具

- このノートの参考資料を探す
- 項目を読む
- `set_goal` でゴールの一文を残す。この文が生成指示になる
- `commit_items` で見出しごとに項目を書く
- `ask_user` で一つ聞いて止める
- `deliver` でゴールを生成指示としてエディタへ渡す
- `write_office_draft` で文書台帳へ下書きのファイルを書く

ファイルサーバは Storage Manager 側の Hermes のままである。この製品のノートからは、あとから A2A で調査結果だけを受け取る。同じ作業を二つの Hermes に頼まない。ファイルの移動、保存先の適用、シェルは含めない。

## 範囲の外

- 別のエージェント画面
- work ディレクトリと、その代わりの専用台帳
- 手続きの提出と台帳の確定
- 源内工房に当たる、利用者ごとの任意コード実行
- スキルの組織横断共有
