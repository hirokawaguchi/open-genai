# 台帳

台帳はフォームから分けたアプリです。フォームの確定は台帳の利用者の一人で、同じ API を直接読む・書くこともできます。

起動は `docker compose --profile ledger up -d` です。画面は `/ledger` です。フォームの古い台帳 URL はここへ移ります。

## 何を持つか

台帳は作ったときの棟に属します。棟に入っていない利用者は作れず、一覧は空です。一覧は今の棟だけです。システム管理者は ID を知っていれば他の棟の台帳も開けます。

棟の中では、チームに管理者・編集者・閲覧者を付けます。作る人は、自分が属するチームを1つ以上、管理者にします。システム管理者はこの指定なしでも作れます。作成者はその台帳の管理者です。閲覧者はマスクした項目の値を見られません。追加項目はマスクできません。

項目の型は text、number、date、select、longtext、file です。台帳ごとに項目と状態名を持ちます。動かしながら項目の追加と表示名の変更、状態名の追加ができます。型の変更と項目の削除はできません。

行には定義項目に加えて、追加項目（名前と文字列）を持てます。追加項目は定義項目へ昇格できます。

保存のたびに、変わった項目の前後を1件の改訂として残します。同時の保存は後の保存が残ります。削除は一覧から隠すだけで、管理者は戻せます。改訂と監査は消せません。

## 入出力

JSON は定義の一覧と行を1つのファイルにします。追加項目は `{label, value}` です。JSONL は同じ行だけで、定義は含みません。この2つが追加項目を往復できます。

CSV は定義項目と担当・状態・コメントだけです。文字コードは UTF-8（BOM 付き）です。知らない列はエラーになり、追加項目にはしません。CSV の読み込みは追加項目を変えません。JSON の読み込みは定義を変えません。知らない項目 ID は、ファイルの表示名で追加項目になります。

添付の中身はファイルに入れません。JSON と JSONL はファイル名と ID だけを持ち、中身は API でやりとりします。見られないマスク項目は、どの書き出しからも除きます。呼び出し方は、台帳を開いた画面の「API」タブに書いてあります。経路は `/ledger` です。

## フォームからの確定

フォームを使うときは台帳アプリの起動が必要です。受理の直前に台帳へ行を作り、台帳が止まっているときや接続先が無いときは受理になりません。

手続きの `handling.field_map` は、回答の表示名と台帳の項目 ID の対応です。対応がない回答は追加項目になります。手続きの台帳は、確定した利用者のチームのうち先頭を管理者にします。チームはあとから台帳の定義で足せます。

## 項目の提案

カードの追加項目からは、同じ名前を設定項目にする案を出します。これはモデルを使いません。マスクした項目とマイナンバーは見本にしません。

定義項目の画面では、既存の資料の文章を貼るか、PDF、Word、Excel、CSV、テキスト、画像（PNG、JPEG）を選ぶと、モデルが管理項目の案を出します。Excel は見出しと見本の行だけを渡します。文字の無い PDF は、ページを画像で選びます。マイナンバーや個人番号の行は送りません。モデルが止まっているときは、その案は受け取れません。項目は手で足せます。

どちらの案も、人が一覧に足してから保存します。すでにある項目は出し直しません。状態の変更、削除、自動の確定はしません。

## 値の出自

項目の値には、入力、取込、推測のどれかを付けます。入力は画面で人が入れた値、取込は資料や登録 API に書いてあった値、推測は資料から補った値です。登録 API で出自を省くと取込になります。出自の無い既存の値は入力として扱います。

推測は取込と入力を上書きせず、取込は入力を上書きしません。人が画面で直すと、その項目は入力になります。

資料からの登録は、設定項目へ入れる値の案を出して止まります。人が残す行を選ぶとレコードになり、出典のファイルをそのレコードへ添付します。1つの資料に複数の対象があるときは、行を分けて出します。状態は変えません。JSON の書き出しには出自を含めます。ファイルは先に画面で見てから、ダウンロードするかを選びます。Word は段落、Excel は表、PowerPoint はスライドの文字として出します。図やレイアウトは含みません。

検索文と申し送り文も提案です。保存は人が押します。状態の変更、削除、自動の確定はしません。

## 文書台帳

オフィスの保存先は、棟に一つの文書台帳です。source_key は `office` です。最初の保存で作られ、名前は「文書」、状態は下書きと確定です。項目は種類とメモです。ファイルの名前は本体のファイル名で、題名という項目は持ちません。業務キーとコメントは一覧に出しません。

明示した役割が無いチームは読み書きできます。読み取りだけにしたチームは、その指定が優先します。作ったチームはオーナーです。

行の本体はファイルひとつです。保存のたびに中身を差し替え、直前のファイルは同じ行に残ります。担当は、その行を保存した人のユーザ名です。同じファイル名でも、カードには保存した時刻を出して版を見分けます。カードのファイル名からオフィスで開き、「この版を現在にする」で戻せます。確定の行の本体を差し替えられるのはオーナーだけです。確定を下書きへ戻せるのもオーナーだけです。

オフィスで開くと、その本体をエディタへ渡します。上限は `LEDGER_OFFICE_MAX_BYTES`（既定 32MiB）です。
